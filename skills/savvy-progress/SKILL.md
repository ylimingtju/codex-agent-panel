# Codex Agent Panel

本技能使用同插件根目录的 `state.py`。从本 SKILL.md 所在目录向上两级即为插件根；下面的命令用该脚本的实际绝对路径。始终在当前代理的原生 shell 执行，保留宿主提供的线程 ID。不要用猜测的聊天 ID、最近会话、PID 或工作目录关联任务。

## 主代理

1. 首次派出子代理后，或用户明确要求跟踪时，运行 `python3 -B <插件根>/state.py open`。如上一轮已结束且现在有新的独立任务，使用 `state.py open --new` 建新轮，保留旧卡。在当前宿主已有轮次时，也可直接调用下列 MCP 工具，由宿主传递当前线程身份。读取返回的只读 `view_key`，调用本插件的 `show_track` 并传入该值。将工具返回的界面交给宿主正常显示。同一轮工作只展示一次；用户明确请求重开时可再次展示。工具尚未可见时，在可用 MCP 工具中查找 `savvy-progress-codex`。只有文字的客户端仍能从工具结果读到摘要。
2. 派工目标已明确且可独立验收时，立即为每项登记任务，例如两名代理各有一个独立交付项，则先登记两个任务并把 ID 对应到各代理。不要等到收尾才声明计划。用 `state.py progress` 加一个 JSON 参数登记 `title`、`phase` 和计划任务数组 `tasks`。每项包含稳定的 `id`、`title`。只知道实际启动了哪些代理时先留空计划，不估算分母。派工时把对应的任务 ID 告诉该 worker。若它没有上报步骤，主代理可通过 `agents:[{"id":"本轮返回的子代理路径或线程 UUID","task_id":"计划 ID"}]` 将原生代理绑定到已登记的任务。需要删去撤回的计划项时传 `remove` 数组。对已有结果返工仍沿用原任务 ID。
3. 收到结果先核查，再用 `progress` 的 `accepted` 数组报告已验收任务 ID。改变阶段时更新 `phase`；必要时用 `reopen` 重新打开任务。任务结果未核实时只报告已有事实。主代理明确收到交付可将该代理标为 `ended`，收尾时独立传 `finished:true`。若因取消或失败停止，保留真实验收数并标明受影响的代理。无需为刷新、动画或计时轮询模型。
4. 用户说“在右侧打开”或“查看子代理详情”时，调用本插件的 `show_panel`，显示当前聊天右侧标签。总进度卡上的“在右侧打开”也会请求同一宿主侧栏。宿主不支持切换时，提示从聊天右侧标签菜单选择“子代理”。首次配对只需要本聊天的只读配对码。

## 子代理

在自己当前的原生 shell 用 `state.py step` 加 JSON 参数报告真实的 `done`、`total`，可带 `note` 和主代理给出的 `task_id`。刚拿到任务时可报告零步；之后仅在步骤变化时更新。总数未知时保留“步骤未报告”。归属无法核实时，以原生消息向主代理回报结果。子代理不用打开总进度卡或验收任务。

新任务不因开启跟踪而要求额外代理、实验、费用估计或通知。独立实验的成功、失败与 ETA 仍遵循 experiment-progress 的规则。
